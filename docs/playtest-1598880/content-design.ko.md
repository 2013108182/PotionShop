# 플레이테스트 1598880 콘텐츠 설계 및 시스템 인계

## 범위와 결정

이 문서는 1598880 빌드의 3일차까지 관찰한 F01–F07을 현 `flutter/` 코드와 대조한 **후속 기획안**이다. 아래 콘텐츠/상태 추가는 이번 버그 수정 범위에 포함하지 않는다. 첫 시도 성공, 무료 실험, 무기한 재시도, 낮 제조와 자금 지원을 유지한다. 실패나 품절을 강요해서 밤 준비의 가치를 만들지 않는다. 그림·사운드는 요구하지 않는다. 4일차 이후 플레이 결과나 장기 경제 균형을 검증했다는 의미가 아니다.

콘텐츠 목표는 `부탁 → 효능과 재료 성질을 연결하는 연구 → 사용 후기 → 소개 → 협회 주문`을 읽을 수 있게 만드는 것이다. 새 보상이나 새 레시피보다 기존 사건을 이해할 수 있는 문구와 정보부터 순서대로 적용한다.

| 요청 | 판단 | 콘텐츠 산출물 | 시스템 인계 | 선행 조건 |
|---|---|---|---|---|
| CR01 / F01 | 채택, 후속 구현 | 답을 직접 주지 않는 후보 안내·단계별 자발적 도움 | SR01 | 연구 화면 현 상태 확인 |
| CR02 / F02 | 채택, 후속 구현 | 후보/보류/제외 표시·메모 문구 | SR02 | 연구별 저장/복원 |
| CR03 / F03 | 예측 먼저 채택, 예약 혜택 보류 | 밤 준비 목록·예상/확정 구분 | SR03 | 실제 주문 데이터, 수요·재고 계산 |
| CR04 / F04 | 단일 알려진 레시피 직접 판매 채택 | 한 번 클릭하는 건네기·고객별 짧은 반응 | SR04 | 알려진 전체 레시피 수 기준 |
| CR05 / F05 | 반응 차별화 채택, 재료 선물은 별도 승인 후 | 로빈 약속/지급 대사와 후속 후기 | SR05 | 안정된 고객ID·성공 이력·1회 이벤트 |
| CR06 / F06 | 콘텐츠 경계 안내 채택, 새 희귀 연구 보류 | 해금 직후 안내·선택 목표, 후속 부탁 후보 | SR06 | 실제 구현된 콘텐츠 목록 |
| CR07 / F07 | 투자 정보 채택, 수요 증가는 보류 | 원가·생산량·회수 조건 설명 | SR07 | 원가 계산·CR03 수요 정보 |

시스템 담당 `/root/system`에게 CR01–CR07을 전달했고 SR01–SR07의 1:1 대응을 확인했다. CR04는 시스템 담당 의견에 따라 '재고가 있는 물약 1종'이 아니라 '**알려진 전체 레시피가 1종이고 해당 재고가 있음**'으로 좁혔다. SR08/F10의 재료 선물 분류와 CR05를 연결한다. 시스템 상세는 [system-spec.ko.md](system-spec.ko.md)를 따른다.

## 코드 대조

- `lib/game.dart`: 기본 재료 6종, 희귀 2종, 레시피 2종. 숙면은 `web→tear→moon`, 시야는 `moon→salt→mushroom`. 1·2일 주문은 고정, 이후는 `laterOrders`를 사용한다. 현재 코드의 반복 구조 확인을 보고서의 장기 관찰로 대체하지 않는다.
- `lib/opening_screen.dart:_beats[8]`: 연구 메모가 달빛 결정→심해 소금→별빛 버섯을 정확한 정답순으로 열거한다. F01의 직접 근거다. `lib/research_screen.dart:shelf`의 전체 6종에서도 이 세 재료가 연속하므로 보조적으로 점검한다.
- `lib/research_session.dart`: 슬롯/시도 이력 저장은 있으나 수동 제외나 자유 메모 필드는 없다.
- `lib/opening_screen.dart:_beats[2]`: 로빈이 “다음에는 제가 재료도 가져올게요!”라고 약속한다. `lib/main.dart:controls`는 일반 영업 성공 문구가 공통이며 재료 지급 이벤트는 없다. 따라서 약속 회수 누락은 확인되지만, 보상 종류·수량·지급 시점은 신규 설계 결정이다. 이번 버그 수정으로 임의 보상을 지급하지 않는다.
- `lib/shop_tasks.dart:guildOrder`: 해금과 영업 지속만 안내한다. `main.dart:milestone`에는 첫 세 날 이야기 종료와 다음 연구용 재료 안내가 별도로 있다. 주력 경로에서 실제 이용 가능한 기능을 분명히 안내해야 한다.
- `lib/game.dart:prepare/brew/upgrade`: Lv2는 재료 1세트로 2병. 이번 검토의 90G·6G·3G 계산은 기본 재료 가격과 Lv1→2에 한정한다.

## CR01: 정답 대신 성질을 읽는 첫 연구

**발생:** 엘리의 미발견 시야 물약 요청이 기록된 밤, 연구 시작 시.

엘리의 부탁은 유지한다. 안내는 다음과 같다.

> “횃불 없이도 밤 숲길을 보고 싶어요.” 빛과 감각에 관련된 재료를 살펴보세요. 서로 다른 세 재료를 고르고, 넣는 순서는 실험으로 알아보아요.

우선 도입부의 스승 메모를 “재료의 성질을 읽고, 물약에 어울리는 세 가지를 골라보렴. 어두운 길을 보려면 빛과 감각에 관련된 성질을 살펴보면 좋겠구나. 넣는 순서는 네 실험 기록에서 찾아보렴.”으로 바꾼다. 특정 재료 세 개를 정답순으로 나열하지 않는 것이 핵심이다.

선반은 고정 순서 `별빛 버섯 → 밤의 거미줄 → 황혼 꽃잎 → 달빛 결정 → 정령의 눈물 → 심해 소금`을 후보로 제안한다. 화면 폭별 읽기 순서에서 정답 세 재료가 정답순으로 연속하지 않도록 한다. 화면을 열 때 임의 재료를 정답처럼 강조하지 않고 “재료를 살펴보면 성질을 읽을 수 있어요.”를 표시한다. 기존 성질 문구는 유지한다. 레시피북의 이미 발견한 숙면 정답은 숨기지 않는다.

사용자가 원할 때 누르는 도움:

1. `작은 단서 보기`: “잠을 재우거나 체온을 올리는 성질보다, 빛과 감각을 살펴보세요.”
2. `실험 기록 읽는 법`: “완벽은 재료와 순서가 모두 맞은 개수, 불안정은 재료만 맞은 개수예요. 어느 칸이 맞았는지는 알려주지 않아요.”
3. `한 번 더 도움받기`: “재료는 그대로 두고 두 칸의 순서를 바꾸면, 앞선 결과와 비교할 수 있어요.”

도움은 실패 횟수로 잠그지 않는다. 특정 정답 재료를 순서대로 열거하지 않는다. 최초 정답 입력도 그대로 성공한다. 실패 결과에는 “아직 다른 반응이에요. 기록을 남겼으니 마음 놓고 다시 해보세요.”를 사용한다.

**수용 기준:** 모든 크기 화면에서 목록·초기 선택·툴팁이 답 배열을 제시하지 않음. 정답 첫 시도 성공. 도움·실험에 G/재료/날짜 비용 없음. 도움 사용 유무가 성공 보상에 영향을 주지 않음.

## CR02: 플레이어가 적는 연구 메모

**발생:** 첫 연구부터 항상 사용 가능. 재료마다 `표시 없음 / 후보 / 보류 / 제외`를 수동 변경한다. “내 메모예요. 실험 결과를 자동으로 판정한 표시는 아니에요.”를 상시 설명한다. 제외해도 실험 선택은 가능하며 “제외 표시한 재료예요. 다시 시험해 볼까요?”와 `넣기 / 돌아가기`를 제공한다.

자유 메모 자리표시: “다음에 비교해 볼 조합이나 궁금한 점을 적어보세요.” 정답 재료 이름을 자리표시에 사용하지 않는다.

**수용 기준:** 연구 재진입과 저장 불러오기 후 표식·메모 유지. 실험 재사용/슬롯 교환은 표식을 바꾸지 않음. 표식으로 점수·보상을 수정하지 않음. 전체 초기화는 `슬롯 비우기`와 `내 메모 지우기`를 분리하고 후자만 확인. CR01의 도움과 충돌하지 않음.

## CR03: 밤의 준비가 이해되는 내일 목록

1차는 신규 경제 규칙 없이 정보만 제공한다. 연구를 마친 직후와 밤 제조 화면에 현재 주문 데이터로 생성한 내일 목록을 보여준다.

| 첫날 밤 예시 | 수요 | 이유/표시 |
|---|---|---|
| 엘리 · 시야 물약 | 1병 | “내일 다시 올게요”가 기록된 방문 예정 |
| 로빈 · 숙면 물약 | 1병 | 내일의 예상 주문 |
| 준 · 시야 물약 | 1병 | 내일의 예상 주문 |

현재 주문표가 고정이라는 사실과 서사 속 약속을 분리한다. 로빈·준을 예약 고객으로 꾸며내지 않는다. 표시 예: “내일 예상: 숙면 1병 · 시야 2병 / 지금 재고: 숙면 {n}병 · 시야 {n}병 / 더 준비하면 좋은 수량: {부족분}”. 미발견 시야는 `연구가 먼저 필요해요`를 붙인다. 발견 보상 1병도 재고 계산에 포함한다.

2일 밤의 협회 영역: “길잡이 조합: 시야 물약 3병 · 마감 없음”. 일반 손님 예상 시야 1병과 협회 3병은 별도 줄에 두고, 협회용 재고를 자동으로 차감하거나 잠그지 않는다. “협회까지 함께 준비하면 총 4병이 필요해요.”는 미납 상태에만 표시한다.

준비의 즉각적 이점은 `주문할 때 바로 건넬 수 있어요`이다. 낮 구매·제조 가격 인상, 강제 대기, 손님 이탈, 밤에만 가능한 필수 제조는 추가하지 않는다.

**보류안:** 예약 수락/취소, 예약 보너스, 할인, 한꺼번에 제조하는 계획 큐. 보너스 수치와 수요 증대는 경제 검증 없이 확정하지 않는다.

**수용 기준:** 표시 수요가 실제 다음 주문 데이터와 일치. 재고 증가/판매/납품 후 부족분 재계산. 조합 보상 완료 시 미납 수량 제거. 준비하지 않아도 낮 제조로 판매 가능. 예상값을 확정 계약으로 표현하지 않음.

## CR04: 단순 주문은 짧게, 선택은 남기기

알려진 레시피가 숙면 1종뿐이고 재고가 있으면 주문 아래 `숙면 물약 건네기 · 35 G`를 직접 노출한다. 사용자가 눌러야 판매한다. 복수 레시피를 알게 된 후에는 선택 UI를 유지한다. 재고가 하나만 남았다고 정답 물약을 자동 추천하거나 연구 답을 드러내지 않는다. 미발견 요청에는 기존 `아직 없어요 · 요청 기록하기`를 유지한다.

성공 후 일반 손님은 짧은 반응으로 다음 손님 이동과 자연스럽게 연결한다. 중요 부탁·소개·새 기능 안내만 별도의 읽기 단계 후보로 둔다. 대사 자동 생략은 별도 검토 대상이다.

**수용 기준:** 1종 상태에서 병 선택 후 별도 확인이 필요하지 않음. 버튼 1회 입력으로 판매 1건만 처리. 복수 레시피에서는 플레이어 선택과 기존 오판매 재시도 유지. 알 수 없는 물약이나 무재고를 판매하지 않음.

## CR05: 받은 도움의 후기와 로빈의 약속

당일 날짜만으로 사용 후기를 보여주지 않는다. 실제 해당 고객 판매 성공 이력이 선행한다. 현재 코드는 날짜별 주문 대사이므로 이력 분기가 신규 기능임을 명시한다.

| 사건 | 성공 이력 있을 때 | 이력 없을 때 |
|---|---|---|
| 로빈 첫 숙면 판매 | “오늘은 푹 잘 수 있겠어요. 다음에 올 때 제 밭의 재료를 조금 가져올게요.” | 첫 성공에서만 이 문구 |
| 로빈 재방문 | “덕분에 잘 잤어요. 약속한 재료도 챙겨 왔답니다.” | “오늘은 숙면 물약을 살 수 있을까요?” |
| 미나 숙면 후기 | “반죽이 부푸는 동안 저도 푹 쉬었어요.” | “내일 새벽에 빵을 구워야 해서요.” |
| 엘리 시야 첫 판매 | “오늘 밤, 숲길 표지판이 잘 보이는지 살펴볼게요.” | 첫 성공에서만 이 문구 |
| 엘리 후기·소개 | “밤길 표지판이 또렷했어요. 길잡이 조합에도 이야기해 둘게요.” | “준비되면 언제든 들를게요.” |
| 준 시야 판매 | “이번에는 주소를 찾아 헤매지 않겠어요. 고마워요!” | 판매 성공 시에만 |

`어떤 효능이 필요하세요?` 확인 질문은 물약 이름만 되풀이하지 않고 직업상 쓰임을 덧붙인다. 로빈: “푹 자고 새벽에 약초를 돌보고 싶어요. 숙면을 돕는 약이면 좋겠어요.” 미나: “내일 일찍 반죽을 해야 해서, 오늘은 편히 자고 싶어요.” 엘리: “횃불이 꺼져도 갈림길 표지판을 읽을 수 있으면 좋겠어요.” 준: “밤에도 집 앞 주소가 또렷이 보이면 배달이 한결 쉬울 거예요.” 질문은 필수가 아니며 추가 가격·효과 차이를 약속하지 않는다. 인물별 문구 선택에도 CR05의 안정된 고객ID를 사용한다.

**선물 신규안:** 도입부 stage 1에서 로빈 숙면 판매 성공 후 stage 2 약속 표시까지 `약속함`을 기록하고, 그 뒤 로빈 재방문 진입 시 밤의 거미줄 1개·정령의 눈물 1개를 1회 지급한다. 도입부에서 일반 영업으로 전환할 때도 약속 상태를 보존한다. 현재 방문 구매를 강제하지 않는다. 표시는 “로빈의 선물 · 밤의 거미줄 +1 · 정령의 눈물 +1”. 기본 가격 기준 총 4G 상당이나 현금 매출로 계산하지 않는다. SR08 정산에는 `받은 재료`로 남긴다.

기존 세이브는 명시적 지급 이력이 없다. 도입부 stage로 약속 대사 도달 여부를 확인할 수 있는 경우와 일반 영업 저장만 남아 지급 여부가 불명확한 경우를 구분한다. 불명확 상태에 소급 선물을 일괄 지급하지 않는다. 이미 들은 약속을 복구하는 정책은 마이그레이션 설계에서 확정한다. 저장/복원 및 중복 방지 작업이 승인되기 전에는 기존 약속에 추가적인 보상 수량이나 기한을 붙이지 않는다.

**수용 기준:** 약속→재방문→재료 증가→후기 순서 추적 가능. 미구매 고객에게 거짓 사용 후기 없음. 재진입/재시작으로 선물이 중복되지 않음. 지급 실패 시 지급 완료 문구를 띄우지 않음. 무료 실험과 기존 자금 지원 유지.

## CR06: 희귀 해금의 의미와 콘텐츠 경계

현재 제공되는 두 레시피에 희귀 재료 사용처가 없다는 코드를 근거로, 해금 직후 주력 협회창에 다음을 제안한다.

> 길잡이 조합에 물약을 보냈어요. 세이지의 희귀 재료 거래가 열렸습니다. 현재 즐길 수 있는 연구 이야기는 여기까지예요. 손님을 맞고, 물약을 만들고, 가마솥을 개선하며 영업을 계속할 수 있어요. 희귀 재료를 지금 사 둘 필요는 없어요.

버튼은 `영업 이어가기 / 재료 살펴보기`. 지속 목표는 선택형 “내일 예상 주문을 준비해 보기”로 CR03과 연결한다. 새 희귀 연구가 실제 존재하지 않는데 “다음 밤 새로운 부탁 도착”을 약속하지 않는다.

**보류 콘텐츠 후보:** 세이지의 “시든 온실의 씨앗을 깨우고 싶어요” 부탁 → 맨드레이크(생명력)+정령의 눈물(안정)+황혼 꽃잎(온기)로 `봄깨움 물약`을 연구하는 후속 장. 요정 가루는 이 부탁과 효능 연결이 약하므로 억지로 넣지 않는다. 이는 제안일 뿐 레시피 정답·순서·가격·수요를 확정하지 않는다. 선행 기능은 복수 연구 ID, 연구별 노트, 부탁/발견/후기 상태, 희귀 재료 연구 접근 정책이다. 무료 연구를 유지하며 희귀 재료 구매를 연구 입장료로 만들지 않는다. 별도 콘텐츠 구현 승인과 플레이 검증 전에는 출시 일정이나 예고 문구에 사용하지 않는다.

**수용 기준:** 해금 직후 실제 사용할 수 있는 기능과 아직 없는 연구가 구별됨. 희귀 구매가 진행 필수처럼 표현되지 않음. 이후 관찰을 수행하지 않고 day4+ 전체 경험에 대한 결론을 내리지 않음.

## CR07: 가마솥 투자를 판단할 정보

Lv1→2 설명 제안:

> 개선 비용 90 G. 같은 재료 1세트로 1병 대신 2병을 만들어요. 기본 재료 3개를 새로 살 때 한 세트는 6 G, Lv2의 병당 평균 재료비는 3 G예요. Lv1보다 병당 3 G가 절약되어, 약 30병을 만들고 판매하면 90 G에 해당하는 재료비를 아낄 수 있어요.

바로 아래 조건을 붙인다: “같은 물약을 짝수 병씩 생산하고 모두 판매하며, 재료를 현재 가격으로 구매하는 비교예요. 지금 보유한 재료와 남는 재고에 따라 실제 지출과 회수 시점은 달라져요.” 회수는 추가 매출이나 순이익 보장을 뜻하지 않는다. 수학적으로 30병 제조 시 재료비 차이가 90G이며, 판매는 남는 재고가 없다는 운영 가정이다.

CR03 영역과 연계해 “내일 예상 주문 {n}병 / 협회 미납 시야 3병”을 함께 보여주되 `지금 개선해야 해요`라는 권고는 하지 않는다. 2–3병/일 전량 판매를 단순 가정하면 약 10–15영업일에 해당하지만, 연구 시점·협회 주문·재고·선물·구매비에 따라 달라져 기본 UI에서 보장 일수로 제시하지 않는다. Lv2→3은 별도 180G 계산이 필요하므로 30병 문구를 재사용하지 않는다.

**수용 기준:** 재료 1세트 수·생산량·새 재료 구매비·보유 재료 차감이 구분됨. Lv2에서 1병 요청이 2병 생산으로 올림되는 실제 규칙이 보임. 90G/30병 문구는 Lv1→2에만 표시. 매출·조합 보상과 원가절감을 합쳐 수익으로 표시하지 않음. 실제 장기 수요 균형 검증은 별도 과제로 남김.

## 적용 순서와 검증 경계

1. 확인된 현재 UI/상태 버그 수정과 회귀 검증은 별도 버그 담당이 수행한다.
2. 승인 후 CR01과 CR04의 작은 표현/조작 개선, CR06의 정직한 종료 경계 안내부터 적용한다.
3. CR02 저장 구조, CR03 수요 표시, CR07 조건부 투자 정보를 구현한다.
4. 고객ID/이력/이벤트 체계를 갖춘 뒤 CR05 대사 및 선물 지급을 함께 적용한다.
5. CR03 예약 혜택·수요 증대와 CR06 새 희귀 연구는 후속 실험/승인까지 보류한다. F11–F14 아트 요구는 이 단계의 의존성이 아니다.

이 문서는 코드 독해에 근거한 설계 산출물이며 플레이테스트나 구현 완료 보고가 아니다. 원본 PDF 전체 4쪽의 Library 추출 텍스트가 `/workspace/review-input/report-library-read.txt`에 로컬 저장되어 있고, 해당 텍스트와 제공된 완전한 F01–F14 개요를 근거로 한다. 이 담당은 로컬 추출 텍스트를 읽었으며 PDF 바이너리를 직접 열지는 않았다. PDF 다운로드 실패의 접근 한계는 상위 담당 결과를 따른다.
