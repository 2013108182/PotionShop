## 적용 범위

- 원형 React 튜토리얼의 세 실험을 별도 교육 상태로 옮겼다. 첫 로빈 판매 전에 단계별 선택과 결과를 익히며, 교육 보상이나 재료 소비는 없다. 기존 저장은 교육을 강제하지 않는다.
- 물약 12종·재료 12종·주민 8명·이야기 32개를 데이터로 정의했다. 제조 접근과 무료 연구 샘플 접근을 분리했다. 시야를 포함한 v2 자유 연구는 카탈로그 12종 샘플을 사용하며, 교육 전용 유니콘 뿔은 일반 창고에 추가하지 않는다.
- 목표별 연구 노트·수동 표식·메모를 저장하고, 미완료 노트의 손상이나 저장 실패를 새 빈 기록으로 덮어쓰지 않는다.
- 주민 부탁→연구→전달→다음 방문 후기→소개와 후속 이야기로 이어진다. 본인이 들은 사실과 약속만 다이어리에 기록한다. 선택형 부탁에는 비물약 경로가 있으며, 판매 반복을 관계 점수로 환산하지 않는다.
- 첫 3일은 고정 방문을 유지하고 이후 하루 세 방문 중 이야기 최대 두 건을 계획한다. 밤에 확인한 다음 날 계획을 저장하여 재접속이나 제조 때문에 바뀌지 않도록 했다.
- F04 단일 알려진 레시피의 반복 판매 클릭, F07 원가·수요·회수 가정 안내, F10 판매/협회/재료/투자 및 놓친 주문 원인을 연결했다. 로빈 재료 약속은 실제 한 번 지급한 기록을 남긴다.
- 저장 실패 시 추가 진행을 막고 재시도를 제공한다. v2 원본을 백업한 뒤 v3으로 옮기며, 이전 수입에서 확정할 수 없는 판매·보상 비율은 임의로 추정하지 않는다.

## 검증과 제한

정확한 검사 결과·환경 증거·재실행 명령은 [QA 기록](qa-results.ko.md)을 참조한다. **Flutter analyze·테스트·빌드·실제 화면 플레이는 아직 실행되지 않았다.** SDK 아티팩트의 공식 다운로드가 HTTP 403으로 차단됐다. 구문 파싱이나 작성된 테스트 수를 컴파일 또는 테스트 통과로 표현하지 않는다.

완전한 Flutter SDK·테스트 엔진·의존성 캐시가 이 클라우드에 제공되거나 공식 다운로드 접근이 허용되면 `bash scripts/verify-v2.sh`를 실행한다. 그 후 첫 판매부터 자유 연구·다음 날 판매·조합 납품·후속 주민·저장 복원을 실제 화면에서 확인해야 한다. 장기 경제, 4일차 이후 재미, 소리, 아트 품질은 별도 플레이 검증 과제다.
